## 2. 问题清单

### 2.1 已修（本次迁移引入）

#### ① 【中】播放链 header / User-Agent 路径的 `trim()` 未对齐 Java 语义（6 处）

- 位置：`player/PlayUrlResolver.kt:279,329,433,468`、`player/PlaybackFetch.kt:149`、`player/thirdparty/ReexPlayer.kt:69`
- 锚点：`host.setWebUserAgent(value!!.trim())` / `host.setWebUserAgent(if (ua == null) null else ua.trim())` / `json.put(key, headers[key]!!.trim())`
- Java 原文（`git show e904581^:…/PlayUrlResolver.java:295,350,452,490`、`git show 6022d20^:…/PlaybackFetch.java:154`、`git show c357978^:…/ReexPlayer.java:71`）全部是 `String.trim()`（**只裁 `<= ' '`**）。
- 成因：Kotlin `trim()` 按 `Char.isWhitespace()` 裁，额外裁 U+00A0（`&nbsp;`）/U+3000（全角空格）/U+2000..U+200A/U+2028/2029/U+FEFF。UA/Referer/自定义 header 来自爬虫 JSON（`playData`、解析接口的 `ua` 字段、`headers` 映射），含 Unicode 空白时两版发给站点的 header 字节不同 → 可能 403 / 取流失败；`ReexPlayer` 还会把裁剪后的值写进 `reex.extra.http_header` 传给外部播放器。
- 严重度：**中**　引入维度：**本次迁移引入**（`e904581`/`6022d20`/`c357978` 均晚于确立该约定的 `303c603`/`a42ea8e`）
- 处置：**已修** —— 6 处改为 `trim { it <= ' ' }`。

#### ② 【中】预载 header 签名与引擎侧缓存 key 口径不一致（1 处）

- 位置：`player/PreloadManagerHolder.kt:295`　锚点：`sorted[key.trim()] = value.trim()`
- Java 原文：`git show 035c4cc^:…/PreloadManagerHolder.java:266` `sorted.put(entry.getKey().trim(), entry.getValue().trim())`（只裁 `<= ' '`）。
- 成因：同仓库新引擎侧 `player/engine/MediaSources.kt:240` 写的是 `sorted[key.trim { it <= ' ' }] = value.trim { it <= ' ' }`，其 KDoc 明写「与预载侧 key 口径一致」；两处对含 Unicode 空白的 header 值产出**不同 key** ⇒ 预载缓存命中失败（静默失效）。
- 严重度：**中**　引入维度：**本次迁移引入**（`035c4cc` 是 player 包最后一笔迁移提交）
- 处置：**已修** —— 与 `MediaSources` 对齐。

#### ③ 【低】同类 `trim()` 语义差（迁移引入的其余 14 处，一并收敛）

- `bean/AbsJson.kt:239,241`（线路 flag 名）、`bean/Depot.kt:19,23`（订阅 URL / 名称）、`player/PlayUrlResolver.kt:202,206`（UA/Referer 判空）、`player/PlaybackFetch.kt:141`（danmaku 地址）、`player/danmu/DanmuLoadController.kt:96`、`player/danmu/Parser.kt:65`、`player/usecase/M3u8PurifyUseCase.kt:90,94`、`player/usecase/WebParseUseCase.kt:40,49,51`
